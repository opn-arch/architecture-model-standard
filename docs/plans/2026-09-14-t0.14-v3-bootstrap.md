# T0.14 — v3 Bootstrap via CAP-DF Cycle

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Bootstrap AMS v3 (Promise-graph model + pipeline_v3) piecewise, driven by the CAP-DF development-flow cycle (INTAKE → GENESIS → WALK → EVOLVE), with the model emerging as it becomes ready to code and legacy code recycled/refactored into v3.

**Architecture:** Every phase is a CAP-DF cycle instance. The model of the target system (CAP-PB) grows before its code; each entity added carries an INV-DF-REGEN score gate (HIGH → autonomous continuation, MEDIUM/LOW → stop for user consultation). Legacy AMS 2.1 code is not thrown away — it is either recycled behind adapters (Phase 11) or refactored into v3 modules (Phases 1–10). Sizing/compression concerns are explicitly waived until Phase 9; correctness and completeness gate everything before then.

**Tech Stack:** Python 3.11+, PyYAML, JSON Schema, existing pytest suite (3746 baseline tests), Promise dataclass, opencode-arch MCP surface.

  parent_id: CAP-DF

### Task 0.5.3 — Define INV-DF-REGEN scoring procedure

The plan references INV-DF-REGEN throughout but the scoring rubric has never been written down. Do it here so Phase 1+ commits can cite it.

**Files:**
- Create: `docs/methodology/inv-df-regen-rubric.md`

Content sketch (author precise wording during execution):

- **HIGH** — entity has (source_paths XOR structured verification block) AND ≥1 realizes/contains/produces relationship AND provenance cites conversation turn or upstream entity
- **MEDIUM** — entity has one of the three, plus intent, but is missing structured verification or relationships
- **LOW** — entity has intent only; no relationships; no verification

Autonomous continuation only on HIGH. MEDIUM/LOW → stop for user consultation.

Commit: `arch(plan-b): T0.14.0.5.3 define INV-DF-REGEN scoring rubric [refs: CAP-DF-GATING] regen: HIGH (0 entities, doc-only)`
