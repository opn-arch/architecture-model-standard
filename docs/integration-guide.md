# Integration Guide

How the Architecture Model Standard integrates with the logs-db Knowledge OS pipeline.

---

## Overview

The `architecture_model` package is installed as an editable dependency in the logs-db virtual environment:

```bash
pip install -e /path/to/architecture-model-standard
```

Two files in logs-db consume it directly:
- `scripts/_pipeline_manifest.py` — shim that re-exports manifest functions
- `scripts/_pipeline_artifacts.py` — imports `enrich_manifest_slice` for artifact generation context

---

## Pipeline Integration Points

### 1. Reality Manifest Generation

**Consumer:** `scripts/_pipeline_manifest.py` (shim)

```python
from architecture_model.manifest import generate_manifest, print_summary
```

**Behavior:**
- `generate_manifest(project_root)` scans the project via AST analysis
- Loads `.architecture-model.yaml` via `get_config(root)` (auto-discovers if missing)
- Produces metrics, functional blocks, interfaces, and module inventories
- Output: `output/{project}/reality-manifest.json`

**Project root resolution:** The pipeline's `cmd_manifest` resolves the project root from `source_config.opencode_dir` in the database. Falls back to CWD if DB lookup fails.

### 2. Artifact Context Enrichment

**Consumer:** `scripts/_pipeline_artifacts.py`

```python
from architecture_model.integrations.pipeline_bridge import enrich_manifest_slice
```

**Behavior:**
- Before each artifact is generated by the LLM, `enrich_manifest_slice()` prepends architectural context from the model
- This gives the LLM structured knowledge about F-blocks, layers, interfaces, and constraints
- The context is token-budgeted to fit within the LLM's context window

### 3. Synthesize Bridge (Auto-Config Writing)

**Location:** `scripts/_pipeline_synthesize.py` → `_write_architecture_config()`

**Behavior:**
- After LLM synthesis produces `architecture_json` and commits to DB
- Fetches `source_config.opencode_dir` from the project's DB record
- Calls `get_config()` to load existing config (or auto-discover)
- Extracts F-blocks from synthesized subsystems
- Merges: replaces auto-discovered blocks with LLM-synthesized; preserves manual blocks
- Writes `.architecture-model.yaml` via `write_config()`
- Wrapped in try/except — failures are non-fatal

### 4. Validation

**Consumer:** `scripts/project_pipeline.py` → `cmd_validate`

```python
from architecture_model.core.validator import validate_model
```

**Behavior:**
- Loads the architecture model YAML
- Validates structural invariants (no orphans, no dangling references)
- Checks entity completeness and relationship consistency
- Returns score (0-100) with issues categorized as errors/warnings/info

## CLI Entry Point

Installed as `architecture-model` via pyproject.toml console_scripts:

```bash
architecture-model init <path>           # Auto-generate .architecture-model.yaml
architecture-model extract <artifact_dir> # Extract model from Tier 1 artifacts
architecture-model validate <model.yaml>  # Validate model invariants
architecture-model slice <model.yaml>     # Extract model subset (by fblock/layer/artifact/status)
architecture-model diff <old> <new>       # Compare two model versions
architecture-model query <model> "question" # Query model structure
architecture-model context <model>        # Generate LLM context from model
architecture-model stats <model>          # Show model statistics
architecture-model impact <model> <entity_id> # Impact analysis
```

## Database Requirements

For pipeline integration, the project needs:
1. A record in the `projects` table with `source_config` containing `opencode_dir`
2. A record in the `systems` table
3. A link in `system_projects` junction table

```sql
INSERT INTO projects (name, display_name, description, status, category, source_config)
VALUES ('my-project', 'My Project', 'Description', 'active', 'tooling',
        '{"opencode_dir": "/path/to/project"}'::jsonb);

INSERT INTO systems (name, display_name, description)
VALUES ('my-system', 'My System', 'System description');

INSERT INTO system_projects (system_id, project_id)
VALUES (<system_id>, <project_id>);
```

## Pipeline Execution Order

For a new project:

```bash
# 1. Create DB records (project + system + link)
# 2. Ingest source files
python -m scripts.project_pipeline ingest --project <slug> --source /path/to/project

# 3. Seed (code intelligence via AST + optional LLM classification)
python -m scripts.project_pipeline seed --project <slug>

# 4. Synthesize (LLM generates architecture JSON, bridge writes config)
python -m scripts.project_pipeline synthesize --project <slug>

# 5. Generate manifest (AST scan using .architecture-model.yaml)
python -m scripts.project_pipeline manifest --project <slug>

# 6. Generate artifacts (LLM produces MBSE documents)
python -m scripts.project_pipeline artifacts --project <slug>

# 7. Validate (check artifacts against manifest)
python -m scripts.project_pipeline validate --project <slug>
```

Or all at once:
```bash
python -m scripts.project_pipeline all --project <slug> --source /path/to/project
```

## Environment Requirements

| Service | URL | Purpose |
|---------|-----|---------|
| PostgreSQL 16 + pgvector | localhost:5432 | Document storage, embeddings, project metadata |
| LLM Relay | localhost:8400 | Enrichment, synthesis, artifact generation |
| Ollama | localhost:11434 | Classification (qwen2.5:7b) |
| PlantUML jar | ~/.local/lib/plantuml.jar | Diagram rendering |
| Chrome | /Applications/Google Chrome.app | PDF generation (headless) |

**Offline mode:** Set `HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1` to prevent HuggingFace download attempts (corporate proxy blocks them).

## Import Patterns

### From standalone package (preferred):
```python
from architecture_model.config.loader import get_config, discover_config, write_config
from architecture_model.manifest import generate_manifest
from architecture_model.core.parser import load_model, save_model
from architecture_model.core.validator import validate_model
from architecture_model.integrations.pipeline_bridge import enrich_manifest_slice
```

### From logs-db shim (backward-compatible):
```python
from scripts._pipeline_manifest import generate_manifest, print_summary
```

### Database session (logs-db specific):
```python
from app.database import async_session  # NOT async_session_factory
from scripts._db import get_async_session  # context manager wrapper
```
